## 仍未解决

关掉 dlopen hook、关 GUI、禁全部 65 个 il2cpp hook 之后：

```
Hachimi: android::main: JNI_OnLoad        ← 最后一条日志
（8 秒后）
exit-info: process=top.niunaijun.blackbox:p0 reason=2 (SIGNALED) status=7   ← SIGBUS
```

即：**崩溃发生在调用原版 `libmain_orig.so` 的 JNI_OnLoad 之后**，也就是 Unity 自己初始化的阶段，
和 Hachimi 的 il2cpp hook 无关。

## 下一步的候选假设（按可能性）

1. **`libmain_orig.so` 用软链的副作用**
   Unity 的 libmain 可能用 `dladdr` 定位自身目录再拼 `libunity.so`；
   软链路径（`files/nativelib/libmain_orig.so`）与真实目录不一致，可能导致它加载到错误的东西。
   → 试：把真实 `libmain.so` **复制**（而非软链）到 nativelib，并让 `libmain_orig.so` 也指向这份拷贝。
2. **Hachimi 的 interceptor 初始化留下的痕迹**
   即使不 hook dlopen，`Interceptor` 仍会初始化 trampoline 页。
   → 试：在 `init_internal` 里连 `Interceptor` 都不创建（加一个 `disable_interceptor` 开关），
     确认"纯加载、零 hook"时游戏能否正常启动。
3. **容器本身的 Unity 兼容性**
   之前没注入 Hachimi 时，游戏能到 bilibili 登录页，说明 Unity 能跑；
   那 SIGBUS 就是 Hachimi 加载后引入的。用 2 可以彻底切开这两者的责任。
